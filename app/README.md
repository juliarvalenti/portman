# Portman.app

Menu-bar app for portman. It shows every running dev server grouped by
project → worktree, with its ports, **true memory footprint** (`phys_footprint`,
not RSS), CPU, and uptime. It flags stale servers and stops them when you ask.
It links `portman-core` directly, the same crate the `portman` CLI uses, so it
never shells out to the CLI.

## Run / build

```sh
cd app
npm install
npm run tauri dev       # Vite on :1430 + the Rust app, with hot reload
npm run tauri build     # → ../target/release/bundle/macos/Portman.app
```

`cargo build -p portman-app` builds only the Rust side. A plain debug binary
loads the UI from the Vite dev server. To make it use the built `dist/`
instead, add `--features tauri/custom-protocol`.

Icons are generated by `npm run icons` (`scripts/make_icons.py`, needs
Pillow). The tray uses `tray-normal.png` as a template image and the colored
`tray-warn.png` and `tray-critical.png` for the other states.

## What it shows

- **Tray**: `4 · 14.2 GB` means four dev servers using 14.2 GB in total. The
  icon turns amber when a server is stale or a vital crosses its alert
  threshold, and red when memory pressure is critical or disk free drops
  below half the threshold. The menu has one line per server, with Open in
  browser / Stop… / Reveal worktree / Copy env. It also has **Reap stale
  (N · X GB)…**, a swap/disk line, Open Portman, and Quit.
- **Window**: a vitals header, then collapsible projects → worktrees. Each
  worktree shows `(branch · slot N)`, "idle — no processes", or **deleted
  worktree**. Each server row has its ports as links (amber when bound off its
  lease), footprint with a 30 s sparkline, CPU, uptime, and a STALE badge.
  Below the projects come Unattributed, Containers, and Heavy hitters.
- Closing the window hides it. The app keeps running in the menu bar and has
  no Dock icon.

The background thread samples every `refresh_secs` (default 2 s). It pushes
each `Snapshot` to the window as a `snapshot` event and refreshes the tray in
place. The tray menu is rebuilt only when the set of servers changes.

## Stopping

Every stop asks first. Tray **Stop…** and **Reap stale…** open the window to
an inline confirm. A stop sends SIGTERM to every process in the server's tree
(`pnpm` → `next dev` → `next-server`) and waits 5 s. If anything survives, the
row offers **Force kill** (SIGKILL). A confirmed reap sends SIGKILL to
survivors after the 5 s grace period without asking again. Processes inside a
`.app` bundle and processes you don't own appear for context only and have no
Stop button. `portman-core` enforces this as well.

With `[reap] auto = true` in `~/.config/portman/config.toml`, the app reaps
stale servers itself and sends a notification for each one. This is off by
default.

## Notifications

You can turn off each kind under `[notifications]` (`stale`, `disk`, `swap`):

- **Stale server**: e.g. "polaris/web next-server has been up 3 days, using
  6.7 GB". At most once per process per day.
- **Disk free below `alerts.disk_free_gb`** (default 10 GB) and **swap above
  `alerts.swap_gb`** (default 20 GB). The swap alert names the top three
  footprints. Each repeats at most hourly while the condition lasts.

**Limitation:** the spec asks for a **Stop** action button on the stale
notification. `tauri-plugin-notification` doesn't support action buttons on
desktop macOS, so the notification only tells you to open Portman, where Stop
is one click away. Unbundled dev builds may also post notifications under the
terminal's name, or need notification permission granted the first time.
